# BlipLink Company Dashboard

The dashboard is a static frontend backed by Supabase Authentication, PostgreSQL, and Supabase Storage. Public account registration is not provided. A BlipLink administrator creates company accounts and gives each company its login credentials.

## Supabase setup

The dashboard frontend is configured for the BlipLink Supabase project in [`config.js`](./config.js). Its `sb_publishable_...` key is intended for browser use; never put a Supabase secret/service-role key in this file.

Run the current [`schema.sql`](./schema.sql) in the Supabase SQL Editor before using the dashboard. If you already ran an earlier version, run the updated file again to enable public business cards, business addresses, and contact exchanges. Before inviting companies:

1. In **Authentication → Settings**, disable public sign-ups. The dashboard has no registration screen, but this Auth setting is also required to prevent self-registration through the Supabase API.
2. Under **Authentication → Users**, create each company user manually with a unique email and password. Confirm the email or send the Supabase password setup/invitation flow before sharing access.
3. Deploy the site with the `dashboard/` directory and `login.html` included. The homepage sends visitors directly to `/login.html`; after sign-in, they are redirected to `/dashboard/index.html` so local static servers open the app instead of showing a directory listing. Opening the dashboard while signed out returns visitors to the sign-in page. The sign-in screen includes a link back to the public homepage.

The `profile-photos` bucket is limited to 5 MB image uploads. Profile images are public so they can load on shared digital cards; upload, update, and delete access remains restricted to the owner’s folder.

## Public digital cards

Each saved profile gets a share URL in the form `card.html?id=<account-id>`. The dashboard’s **View card** button opens it in a new tab, and **Share** or **Copy link** shares its address. Public cards include a QR code, direct email/phone/WhatsApp/website actions, social links, and a downloadable contact file.

Visitors can submit a contact exchange after explicitly consenting. Those contact details are stored in `card_contact_exchanges`; only the associated company account can read them in its dashboard. The QR image is generated by the QR Server image API from the public card URL. Apple and Google Wallet controls are visibly marked as unavailable until the wallet issuer/pass integrations are configured; no wallet pass is issued yet.

## Included

- Email/password sign-in and sign-out, with no register form or sign-up action.
- A clean `/login.html` sign-in route; the dashboard app remains separate and requires an active session.
- Responsive dashboard with profile editing and a live preview.
- Public, responsive digital business cards with contact actions and downloadable vCard contacts.
- QR codes, card sharing, consent-based contact exchange, and an owner-only connections inbox.
- Per-account card link with one-click preview and copy actions.
- Profile photo upload and removal.
- Website, LinkedIn, Instagram, and X profile link editing.
- English-only dashboard UI; public website language selection remains separate.

For local testing, serve the site over HTTP (for example, VS Code Live Server); browser authentication and storage do not work reliably from `file://`.
